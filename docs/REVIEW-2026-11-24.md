# Independent review — 2026-11-24

> **Status:** All 13 findings resolved (2026-11-24). Recommended corrections applied across repository documentation.
> **Reviewer:** MiMo V2.6 Flash (OpenCode).
> **Scope:** all repository Markdown (README, CONTRIBUTING, SECURITY, LICENSE, docs/*), cross-links, diagrams, status labels, decision log and roadmap sequencing.
> **Method:** full read of the documentation foundation; cross-document consistency, safety-sequencing and completeness checks; relative-link verification (all resolve).

Severity: **High** = safety or cost-control gap; **Medium** = design inconsistency or missing control; **Low** = clarity or process. Status of every finding: **Resolved**.

## Findings

### F-01 — Budget gate not scheduled [High]

**Observation:** D-013 (Accepted: reserve against a budget before every billable dispatch) first appears as enforcement in v0.2/v0.3; v0.1 ships paid requests with visibility only.
**Recommended correction:** Add a minimal pre-dispatch reservation gate to v0.1 exit criteria, or state when D-013 takes effect.
**Refs:** docs/DECISIONS.md D-013; docs/ROADMAP.md v0.1–v0.3; docs/ARCHITECTURE.md key rules.
**Resolution:** Resolved. Added minimal pre-dispatch reservation check to v0.1 deliverables and exit criteria in `docs/ROADMAP.md`. Documented the staged enforcement schedule in `docs/DECISIONS.md` under D-013 (v0.1 minimal gate -> v0.2 daily/monthly limits & reflection budget -> v0.3 multi-agent reservations).

### F-02 — Permission-layer gap in diagrams [Medium]

**Observation:** Only Otto has an edge to the permission layer in docs/ARCHITECTURE.md and the README diagram; Scout's "restricted retrieval" has none, contradicting the rule that no agent bypasses the permission layer.
**Recommended correction:** Add Scout→PERM (and an agent-tool rule note) to both diagrams.
**Refs:** docs/ARCHITECTURE.md component map, responsibilities; README architecture diagram.
**Resolution:** Resolved. Added `SCOUT --> PERM`, `PERM --> WEB`, and `PERM --> TOOLS` in both `docs/ARCHITECTURE.md` (canonical) and `README.md`. Explicitly stated the rule that all agent access to external tools, devices, and web retrieval is strictly mediated by the permission layer.

### F-03 — Meter/gateway arrows inconsistent [Low]

**Observation:** docs/ARCHITECTURE.md shows METER→CLOUD; README shows METER→GW; the request lifecycle has the gateway dispatching while consulting the meter.
**Recommended correction:** Standardise both diagrams on gateway→provider plus gateway⇄meter (reserve/settle).
**Refs:** docs/ARCHITECTURE.md component map and sequence diagram; README architecture diagram.
**Resolution:** Resolved. Standardized both diagrams in `docs/ARCHITECTURE.md` and `README.md` to `GW <--> METER` (reserve/settle) and `GW --> CLOUD` / `LOCALLLM`.

### F-04 — v0.1 never names the Neon role [Low]

**Observation:** Neon is the primary conversational voice per docs/ARCHITECTURE.md and docs/PERSONALITY.md but first appears in v0.3 deliverables.
**Recommended correction:** State in v0.1 that conversation runs on the Neon role.
**Refs:** docs/ROADMAP.md v0.1, v0.3; docs/ARCHITECTURE.md logical agents.
**Resolution:** Resolved. Explicitly stated in `docs/ROADMAP.md` that v0.1 text conversation runs on the Neon role as the primary conversational voice.

### F-05 — Model-config ambiguity [Low]

**Observation:** "Bunny's configured conversational model" does not say whether Bunny and Neon share one model configuration.
**Recommended correction:** Add one mapping sentence in docs/ARCHITECTURE.md (Bunny's voice uses Neon's model by default; per-agent override only when explicitly configured).
**Refs:** docs/ARCHITECTURE.md logical agents; docs/PERSONALITY.md portability section.
**Resolution:** Resolved. Added explicit mapping sentence in `docs/ARCHITECTURE.md` under Logical agents: "Bunny's voice uses Neon's model configuration by default; per-agent model overrides apply only when explicitly configured by the user."

### F-06 — Missing security contact [Low]

**Observation:** SECURITY.md falls back to a "listed security contact" that exists nowhere; CONTRIBUTING.md references discussions while GitHub Discussions is disabled (issues are enabled).
**Recommended correction:** Enable private vulnerability reporting, document a contact channel, and adjust the CONTRIBUTING wording before public launch.
**Refs:** SECURITY.md reporting section; CONTRIBUTING.md "Before opening an issue".
**Resolution:** Resolved. Updated `SECURITY.md` to cite GitHub private vulnerability reporting with fallback contact `security@bunny.ai` (or repository profile contact). Updated `CONTRIBUTING.md` to note that GitHub Discussions is disabled during pre-release and direct questions to issues.

### F-07 — Provider-aware rate limiting, retries and charge accounting [Medium]

**Observation:** The gateway lists "rate-limit, timeout and error normalisation" but the design specifies no bounded-retry policy (attempt caps, exponential backoff with jitter, Retry-After honouring), no per-provider concurrency limits, and no settlement rule for uncertain charges arising on retry/timeout paths beyond key rule 4.
**Recommended correction:** Add a gateway resilience subsection: maximum attempts, backoff + jitter, Retry-After handling, per-provider concurrency caps, and explicit uncertain-charge settlement when a retried request may have been billed.
**Refs:** docs/ARCHITECTURE.md model gateway, key rules 2 and 4; docs/DECISIONS.md D-013.
**Resolution:** Resolved. Added "Gateway resilience and charge accounting" subsection in `docs/ARCHITECTURE.md` specifying max attempt caps (default 3), exponential backoff with jitter, `Retry-After` adherence, per-provider concurrency caps, and uncertain-charge reservation holds until reconciled. Updated `docs/DECISIONS.md` D-013.

### F-08 — Versioned pricing configuration and hard spending controls [Medium]

**Observation:** The budget meter must "reserve, record and settle" and the gateway does "cost estimation", but no document defines versioned price tables (provider, model, effective dates), behaviour on stale or missing pricing (fail-open vs conservative deny), or the split between soft warnings and hard caps enforced in code.
**Recommended correction:** Specify versioned pricing configuration with an explicit stale/missing-price policy (conservative estimate or deny, never silent zero) and distinguish soft alerts from hard spending controls in docs/ARCHITECTURE.md, tied to D-013.
**Refs:** docs/ARCHITECTURE.md budget meter and gateway; docs/DECISIONS.md D-013; docs/ROADMAP.md v0.2.
**Resolution:** Resolved. Added "Pricing configuration and spending controls" subsection in `docs/ARCHITECTURE.md` defining versioned price tables, stale/missing price policy (conservative deny or ceiling; never silent zero), and clear distinction between soft warning alerts and hard code-enforced spending caps. Added to `docs/DECISIONS.md` D-013 and `docs/ROADMAP.md` v0.1/v0.2.

### F-09 — Security/threat-model review sequenced after tool exposure [High]

**Observation:** The completed security review sits at v1.0, after v0.3 (device control) and v0.4 (MCP integration, external skills) deliver world-affecting tools; SECURITY.md and DECISIONS leave review scope and timing open.
**Recommended correction:** Make a threat-model/security review a gate before or at entry to v0.3 and again before v0.4, not only at v1.0.
**Refs:** docs/ROADMAP.md v0.3–v1.0, sequencing notes; docs/DECISIONS.md open questions; SECURITY.md.
**Resolution:** Resolved. Added staged security review gates to `docs/ROADMAP.md` (prior to v0.3 actuation, prior to v0.4 MCP/skills, and final review at v1.0), documented the security review lifecycle in `SECURITY.md`, and marked review timing settled in `docs/DECISIONS.md`.

### F-10 — Network egress and SSRF protection missing [Medium]

**Observation:** SECURITY.md covers ingress ("no default public listeners") but nothing constrains outbound requests from tools, MCP servers or web fetch: private-range destinations (loopback, link-local, RFC1918), redirect chains to internal hosts and DNS rebinding are unaddressed.
**Recommended correction:** Add egress controls to the security model: destination validation against private ranges, redirect-target revalidation, response-size caps and an explicit allow/deny policy for tool-initiated requests.
**Refs:** SECURITY.md intended security model; docs/ARCHITECTURE.md trust boundaries; docs/ROADMAP.md v0.4.
**Resolution:** Resolved. Added network egress and SSRF controls to `SECURITY.md`, `docs/ARCHITECTURE.md` (Trust boundaries), and `docs/ROADMAP.md` exit criteria (v0.3/v0.4), specifying destination IP validation against private/reserved ranges, redirect hop revalidation, DNS rebinding defence, response-size caps, and tool egress allowlists.

**Recommended correction:** Designate docs/ARCHITECTURE.md as canonical; keep the README view a clearly labelled simplified derivative with matching edge semantics.
**Refs:** docs/ARCHITECTURE.md; README.
**Resolution:** Resolved. Explicitly designated `docs/ARCHITECTURE.md` component map as the canonical architecture diagram. Labeled `README.md` diagram as a simplified derivative with identical edge semantics.

### F-12 — No adopted code of conduct [Low]

**Observation:** CONTRIBUTING.md has only an informal "Conduct" paragraph ("a formal code of conduct may be adopted"); DECISIONS lists governance and a formal code of conduct as open, but no standard CoC text or enforcement contact exists.
**Recommended correction:** Adopt a standard code of conduct (e.g., Contributor Covenant) with an enforcement contact, linked from CONTRIBUTING.md and README, before accepting community contributions.
**Refs:** CONTRIBUTING.md conduct section; docs/DECISIONS.md open questions.
**Resolution:** Resolved. Created `CODE_OF_CONDUCT.md` with explicit community standards, unacceptable behaviours, and maintainer reporting contact `conduct@bunny.ai`. Linked from `CONTRIBUTING.md`, `README.md`, and marked settled in `docs/DECISIONS.md`.

### F-13 — Runtime context engineering unspecified [Medium]

**Observation:** The orchestrator must "assemble bounded context" and memory retrieval must be bounded, but no document specifies selective-retrieval composition or per-request token budgets across personality + history + memories, composition order, summarisation triggers for long histories, or cache-aware usage accounting (provider prompt-cache reads are cheaper and should be modelled by the usage meter).
**Recommended correction:** Add a context-engineering section (docs/ARCHITECTURE.md or a new doc): layer budgets and composition order, summarisation triggers and ownership, and cache-aware cost accounting in the gateway/meter.
**Refs:** docs/ARCHITECTURE.md orchestrator, gateway, budget meter; docs/MEMORY.md retrieval and summaries.
**Resolution:** Resolved. Added "Runtime context engineering" section in `docs/ARCHITECTURE.md` specifying layer budgets, strict composition order (Layer 1 -> Layer 2 -> Layer 3 -> summaries -> rolling history -> user turn), selective retrieval limits, Otto background summarisation triggers, and cache-aware usage accounting in gateway/meter. Cross-referenced in `docs/MEMORY.md` and `docs/DECISIONS.md`.
